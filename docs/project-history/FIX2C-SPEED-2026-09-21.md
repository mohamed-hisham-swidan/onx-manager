**Date**: 2026-09-21  
**Scope**: Elimination of real wall-clock delays in `test_fakeplayer_real_verification.py`  
**Target File**: `backend/tests/infrastructure/test_fakeplayer_real_verification.py`  

---

## 1. Root Cause Analysis

During initial test runs, `test_fakeplayer_real_verification.py` stalled at 25% (and took 50+ seconds across the suite). Five distinct root causes were identified:

1. **Unconditional 120s Boot Timeout Floor**:
   In `test_runner.py` line 761:
   ```python
   boot_timeout = max(getattr(bot_cfg, "connect_grace_seconds", 60.0), 120.0)
   ```
   Even when `connect_grace_seconds` was configured down to `0.01s`, the 120.0s floor kept the boot-gate active if log checks or container inspections did not immediately resolve.

2. **Unmocked Database Persistence (`_persist_test_outcome` & `_persist_runtime`)**:
   `DockerTestExecutionRunner._execute_verification` called `_persist_test_outcome` and `_persist_runtime`. In unit test environments without initialized database transactions, calls to `database.session_factory()` attempted real SQLite operations, encountering locks and exponential backoff sleeps (`asyncio.sleep(0.05 * 2**attempt)`).

3. **Real Wall-Clock Sleeps**:
   - `asyncio.sleep(0.5)` in `boot-gate` polling loop.
   - `asyncio.sleep(min(duration_s, 1.0))` following bot commands.
   - `asyncio.sleep(0.5)` in `SmokeTestRunner.run_smoke_test`.
   Without mocks, these accumulated multiple seconds per test case across 10 runner test cases.

4. **Class Mock Descriptor Binding in Python 3.14**:
   In `test_fakeplayer_wiring_unreadable_log_downgrades`, `patch.object(Path, "read_text", side_effect=flaky_read_text)` installed a `MagicMock` descriptor on class `Path`. When `instance.read_text()` was invoked, `MagicMock` called `flaky_read_text` with bound args that omitted `self`, raising `TypeError: flaky_read_text() missing 1 required positional argument: 'self'`. The boot-gate caught this as a generic exception and retried in a tight loop until hitting the 120s timeout.
   *Fix*: Switched to `patch.object(Path, "read_text", new=flaky_read_text)` which uses Python's standard function descriptor protocol to correctly bind `self`.

5. **204-byte Mock Jar Failing `_MIN_JAR_SIZE`**:
   `_setup_runner_spec` initially wrote 204 bytes (`b"PK\x03\x04" + b"\x00" * 200`). `is_fakeplayer_artifact_usable` delegates to `validate_jar`, which enforces `_MIN_JAR_SIZE = 1_048_576` (1MB). Because 204 bytes < 1MB, the pre-launch pipeline determined the artifact was invalid/missing and attempted a network download via Modrinth `ensure_plugin_artifact()`. Under socket blocking, this raised a network error.
   *Fix*: Updated `_setup_runner_spec` to write `b"PK\x03\x04" + b"\x00" * 1_048_576` (1MB valid zip magic).

6. **Variable Scope in `_execute_verification` Finally Block**:
   `plugin_enabled`, `spawn_ok`, `spawn_failed`, etc., were declared inside the `else:` branch of `if boot_passed:`. If boot failed or an exception occurred earlier, accessing `plugin_enabled` in the `finally` block raised `UnboundLocalError`, crashing the background task before `handle.set_result` was called, causing `handle.wait_for_completion()` to hang indefinitely.
   *Fix*: Initialized `plugin_enabled`, `spawn_ok`, `spawn_failed`, `actions_ok`, `actions_failed`, `bot_names_prefix` at the top of `_execute_verification`.

## 2. Applied Fixes & Patches

In `test_fakeplayer_real_verification.py`, every test invoking `run_test(spec)` now patches:
```python
patch.object(StorageCapabilityProbe, "assert_supports_reflink", return_value=None),
patch.object(ResourcePreflightProbe, "assert_sufficient_resources", return_value=None),
patch.object(runner, "_persist_test_outcome", new_callable=AsyncMock),
patch.object(runner, "_persist_runtime", new_callable=AsyncMock),
patch("asyncio.sleep", new_callable=AsyncMock),
patch("subprocess.run", side_effect=mock_subprocess),
```

And in `test_bot_verification_regression.py`, the corresponding async/persistence/sleep mocks were added to all runner tests.
