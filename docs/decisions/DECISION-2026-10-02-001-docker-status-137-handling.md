## Context
In commit `4893f80`, `DockerProvider.status()` was modified to map exit codes 137 (`SIGKILL`) and 143 (`SIGTERM`) to `ServerRuntimeStatus.STOPPED` to eliminate a false `"still running after stop"` warning when stopping containers.

However, exit 137 is also generated by the Linux kernel OOM killer and external process termination (`kill -9`). Because `status()` is a stateless query consumed by `RuntimeSupervisor`, `reconciliation.py`, and `get_runtime_diagnostics.py`, mapping 137 to `STOPPED` unconditionally causes unexpected container crashes and OOM terminations to silently read as clean `STOPPED` states outside the stop flow, breaking runtime crash detection.

Simultaneously, `delete_server.py` deletes and commits the server record from the database before removing the filesystem directory. On permission failures (e.g. root-owned container files), the API returns HTTP 500 (`FILESYSTEM_CLEANUP_FAILED`). Retrying returns 404, leaving orphaned directories without actionable user guidance.

---

## Evidence
1. **FACT:** `DockerProvider.status(handle)` only inspects `{{.State.Status}} {{.State.ExitCode}}`. Outside an operator-initiated stop, an OOM kill or external `SIGKILL` produces exit code 137. Under `4893f80`, this maps to `ServerRuntimeStatus.STOPPED`.
2. **FACT:** `RuntimeSupervisor._health_check` (`supervisor.py:375-397`) checks `is_crash = status != ServerRuntimeStatus.STOPPED or (diag and diag.failure_code is not None) ...`. If `status` is `STOPPED`, crash recovery is bypassed when diagnostic collection is incomplete or inconclusive.
3. **FACT:** In `supervisor.py:98-105`, `stop_for()` sets `self._stop_event` before `stop_server.py` invokes `provider.stop()`. Lines 372-373 and 526-532 explicitly suppress crash handling when `_stop_event.is_set()`. Therefore, `RuntimeSupervisor` already distinguishes requested stops from crashes via `_stop_event`. Reverting `status()` to return `ERROR` on exit 143/137 does not cause `RuntimeSupervisor` to treat requested stops as crashes.
4. **FACT:** `get_runtime_diagnostics.py:68` queries `(await provider.status(handle)).value`. An OOM-killed container returns `"stopped"`, masking the crash in the management API.
5. **FACT:** `DELETE /api/v1/servers/{server_id}` is protected by `require_permission("server:delete")` (`servers.py:321`), granted only to the `owner` role or instance administrators (`bootstrap_instance.py:60`). Disclosing `leftover_path` to this authenticated administrator is safe and necessary.
6. **FACT:** The root-owned directory orphan in triage (`.onx/tests/<uuid>/.paper`) originated from `test_runner.py` prior to the `--user` flag enforcement (`docker.py:393`), not from the itzg image.

## Options

### 1. Option 1 (WITHDRAWN — record only): Revert `status()` & Handle Stop Signals via Provider Interface
- **Withdrawal reason (Build pre-checks):** (P1) `RuntimeDiagnostics` has no `oom_killed` field (`domain/diagnostics.py:36-53`), so Path 1A's `getattr(diag, "oom_killed", False)` gate is dead code — OOM distinction in the stop flow would need an interface change after all; (P2) exited 143/137 persists after `docker stop`, so reverted `status()` reports provider `ERROR` permanently on cleanly stopped servers. Withdrawn in favor of Option Z below; original text kept as record.
- **Provider Contract (as formerly proposed):** Revert `DockerProvider.status()`: exit code 0 maps to `STOPPED`; any non-zero exit code (including 137, 143) maps to `ERROR`.
- **Exit Code Retrieval in Application Layer (as formerly proposed):** In `stop_server.py` and `restart_server.py`, when `provider.status(handle)` returns `ERROR`:
  - **Path 1A (formerly recommended):** Call the existing polymorphic method `diag = await provider.collect_diagnostics(handle)` defined on `ServerProvider` (`base.py:150`) and implemented across all 3 providers. Inspect `diag.exit_code`. If in `(137, 143)` and not `OOMKilled`, confirm as normal stop termination without warnings. **Zero signature changes to `base.py`.**
  - **Path 1B (Alternative):** Change `ServerProvider.stop()` return type to `StopResult(stopped: bool, exit_code: int | None)`. Modifies `base.py` and all 3 concrete providers.

### 2. Option Z (Adopted — Revision 2): OOM Awareness Inside `DockerProvider.status()` Only
- **Change:** inspect format `"{{.State.Status}} {{.State.ExitCode}} {{.State.OOMKilled}}"` in the existing single `docker inspect` call (`docker.py:645-650`); in the `exited` branch, `OOMKilled=true` → `ERROR`, otherwise keep `4893f80` mapping. Parsing mirrors the identical daemon-field parse in `collect_diagnostics` (`docker.py:876`). No interface, enum, `RuntimeDiagnostics`, or consumer change.
- **Why it wins:** keeps clean stops honest (S2/S3/S7 matrix cells identical to X) while restoring `ERROR` for daemon-confirmed OOM kills in every consumer; S5 external kills remain covered by the supervisor's `collect_diagnostics` OR-clauses while the container exists (spec §4.3). Accepted residuals: unconfirmed-kill status string + removed-container case (spec §5 R1).
- **Decision Level:** **D0** (see header).

### 3. Option 2 (superseded by Z — record only): Map by `(exit_code, OOMKilled)` in `status()`
- Inspect `{{.State.OOMKilled}}` in `status()`. If false, map 137 to `STOPPED`.
- *Rejection Reason:* `(exit 137, OOMKilled=false)` is ambiguous outside the stop flow (e.g. host `kill -9` or untracked OOM kills of container child processes). It silently masks crashes from `RuntimeSupervisor`.

### 4. Option 3 (rejected — record only): Return a Richer Status Object from `status()`
- Change `ServerProvider.status()` return type to `RuntimeStatusDetail` or expand `ServerRuntimeStatus` enum with `OOM_KILLED` and `SIGKILLED`.
- *Rejection Reason:* Alters `status()` signature across `base.py`, all providers, and ~8 consumers, causing excessive churn for a D1 issue.

---

## Decision
Adopt **Option Z** (Revision 2; Option 1 withdrawn above):
1. **OOM-bounded Provider Status:** `DockerProvider.status()` keeps the `4893f80` mapping and adds `OOMKilled=true` → `ERROR` in the `exited` branch via the extended inspect format. No consumer, interface, enum, or `RuntimeDiagnostics` change.
2. **Stop Flow:** unchanged code — clean stops (0/137/143, `OOMKilled=false`) keep reading `STOPPED`; no `collect_diagnostics` coupling in `stop_server.py` / `restart_server.py`.
3. **Delete Honesty:** Retain HTTP 500 (`FILESYSTEM_CLEANUP_FAILED`). In `details`, provide `leftover_path` (justified under `server:delete` role check) and a neutral `cleanup_hint` stating the failure "may be caused by file permissions or active file locks". Do not output ready-made shell commands (`sudo rm -rf`).
4. **Deferred Items (Part C):** Keep automatic root cleanup container (D2, security-critical) and `DELETING` state (D1/D2) recorded and deferred.
5. **Separate Itzg Finding (Part D):** Record the `itzg` UID/GID finding and its migration risks as an independent open finding in `STATE.json` without designing the fix.
6. **Accepted residuals (R1):** unconfirmed-kill (137/`OOMKilled=false`) status string and the container-removed case — see spec §5 matrix and §7.3 task-5 finding (diagnostic misattribution recorded separately, no design).

---

## Why
- **Smallest honest change:** one provider-internal branch plus tests restores daemon-confirmed OOM visibility without touching any consumer, interface, enum, or diagnostic object — the revert's permanent-`ERROR` cost (P2) and the stop-flow coupling's interface cost (P1) both disappear.
- **Crash visibility where it counts:** `RuntimeSupervisor`, reconciler edge cases, and the `provider_status` string all read `ERROR` for OOM kills; external kills stay covered by the supervisor's diagnostics coupling while the container exists (spec §4.3).
- **Security & Hygiene:** Removing shell command generation from API payloads eliminates injection and destructive copy-paste risks.

---

## Impact
- **Product/user:** Crashed/OOM servers reliably report as CRASHED and recover. Administrators encountering delete failures get the exact leftover path and a clear explanation.
- **Stability:** High positive impact. Prevents wedged/crashed containers from masquerading as safely stopped.
- **Architecture:** Zero signature changes to `base.py`. Decoupled hexagonal architecture preserved.
